# Decisions

- Rust + PostgreSQL + WebSocket; Svelte SPA embedded in the binary. Reason: performance, one-image delivery.
- Reverse proxy is optional: app speaks plain HTTP; Caddy (default) or nginx via compose profile. Reason: Caddy gave trouble in ribbitto and may limit performance.
- OpenAPI generated from Rust, committed, diff-checked in CI. Reason: future native clients (Kotlin).
- `organization_id` on every table from day one. Reason: multi-organization later without retrofit.
- Minimal docs. Reason: AI credit cost.
- Public repo. Reason: free CI minutes.
- Schema CI discovers migrations at test runtime (so cached binaries cannot miss new files), then inspects every non-system table for NOT NULL `organization_id`, exempting only `public.organizations` (tenant root) and `public._sqlx_migrations` (SQLx bookkeeping). Migration history is append-only against the PR base SHA or the previous main commit; rename detection is disabled so moves cannot hide deletions.
- Authentication is scoped by `organization_id` (returned by setup) plus normalized email; users are organization memberships. The organization row is its own tenant root. The global, table-locked setup check is unscoped because it must refuse setup if any organization exists.
- Web cookies and native bearer auth share an opaque, random 256-bit session credential, with an organization prefix and only its SHA-256 hash stored. Sessions expire after 30 days and sign-out revokes both forms. Cookies are HttpOnly, SameSite=Strict, Secure by default; `FUKULOW_COOKIE_SECURE=false` is for local HTTP only. Password hashing/verification runs on at most four blocking workers with Argon2id to bound memory use.
- Runtime migrations run before listening; PostgreSQL 18 persists under `/var/lib/postgresql`. `make api` exports the Rust contract without connecting to the database and generates TypeScript declarations with pinned `openapi-typescript` in an isolated npm tool environment (its TypeScript 5 peer is incompatible with the SPA’s TypeScript 6 dependency). CI diff-checks both artifacts.
- Optional `FUKULOW_SETUP_TOKEN` gates setup after JSON body extraction but before semantic input validation or database access with constant-time digest comparison and generic 401; set it before public exposure. Unset preserves bootstrap behavior; explicitly empty values fail startup before database access.
- Sign-in may omit `organization_id` only when exactly one organization exists (otherwise 400); this bounded global discovery is a tenant-scope exception, while credential lookup and sessions remain organization-scoped.
- Setup checks global organization existence without a lock before Argon2 work, after token gating and validation; the locked transactional check remains authoritative for concurrent bootstrap requests.
- Setup and sign-in map JSON extraction failures to `ErrorBody`: invalid JSON or fields use 400, unsupported content type uses 415, and the 16 KiB body limit uses 413. CI probes health through Caddy HTTPS with local certificate verification disabled to exercise proxy routing and TLS startup.
- Keep setup body extraction before token verification: extraction errors are generic and reveal neither the configured token nor bootstrap state. Document and test this precedence instead of rewriting the handler; semantic validation, hashing and database access remain token-gated.
- `GET /api/v1/setup` is public and read-only, returning only `setup_required` with `Cache-Control: no-store` so the web can choose setup or sign-in. It shares POST setup's global organization-existence check (one `SELECT EXISTS` query); organization, member and setup-token details remain private.
- Workspace lints forbid `unsafe` everywhere and deny `unwrap`/`expect`/`panic!` in production; Clippy permits panicking test helpers under `#[cfg(test)]`. Negative compilation fixtures use the real manifests and Clippy configuration to guard enforcement and test exclusions (#32).
- Module dependency direction (`realtime` -> `messages` -> `channels` -> `auth`, with `main`/`openapi`/`lib` as composition exceptions) remains Tier 2/review-only under #32's fallback. Source scans need Rust name resolution for aliases, re-exports and macro-generated references.
  A compiler-probe attempt marked higher modules deprecated and forbade deprecated references in lower modules. It detected imports, code paths, `super::`, aliases and macro output, but missed `auth` using `crate::messages::Channel` when `messages` re-exported a non-deprecated `channels::Channel`; rustc accepted that forbidden path. No incomplete check or new dependency is landed. Future modules require the same review until a reliable check is available.
- Rules have tiers: Absolute (CI-enforced, only with a reliable automated check), Default (deviation needs a one-line reason in the PR), Free. Languages are a default, not an absolute (new languages still need maintainer approval). Reason: hard rules without a good check push AIs into awkward code; boundaries and tenant isolation are the exceptions worth enforcing (#29).
- One crate with module boundaries (`auth` <- `channels` <- `messages` <- `realtime`, no reverse edges), each module owns its tables; revisit crates only when build time, dependencies or conflicts hurt. Reason: cross-crate refactors are costly for AI-driven work.
- `unwrap`/`expect`/`panic!` are denied outside tests and `unsafe` is forbidden; gitleaks (SHA-pinned Action, PR and main, full history on first run) guards secrets in the public repo.
- #23 publishes channel/message REST types and `ClientMessage` / `ServerEvent` before runtime work (#22/#17/#18/#19); the new handlers remain 501 stubs. Message pages use exclusive `after_seq` XOR `before_seq` (neither = latest), default limit 50 / max 200, always ascending seq; `has_more` follows the queried direction, continuing with the last seq for after / first seq for before (latest continues before).
- `ListMessagesQuery` keeps all fields optional in the shared schema. Put the limit default of 50 only on REST query-parameter metadata so generated shared TypeScript also accepts an omitted limit; both schemas retain minimum 1 / maximum 200.
- WebSocket upgrade is `GET /api/v1/ws` (101); auth is session cookie with the #18 allowed-Origin check or native Bearer without requiring Origin, never a query token. Rust serde-tagged `ClientMessage` (subscribe with per-channel exclusive after_seq, 0 = start; unsubscribe) and `ServerEvent` (message, subscribed with caught_up_seq, error with optional channel_id) are registered schema roots with oneOf/discriminator `type`; utoipa-derived variants are lifted into named components for discriminator references.
- Sign-in uses process-local 60-second windows: 20 failures per IPv4 address or IPv6 /64 (IPv4-mapped IPv6 shares the IPv4 key), 5 per (organization, normalized email); in-flight attempts reserve capacity before Argon2, and only failed credentials persist. Restarts reset limits; multiple instances need a shared limiter before deployment.
  Each map holds at most 10,000 keys and prunes expired idle entries once per window. IP buckets with no failures or reservations are removed immediately; at capacity the oldest idle IP bucket is evicted, trading retained failure history for admission of new clients. Active reservations are never evicted; a map full of reservations, or a full account map, refuses new keys (429 + Retry-After). Forwarded IPs are ignored unless both an exact proxy peer allowlist and header are configured; use the rightmost IP appended/overwritten by Caddy/nginx, otherwise the socket peer.
- The per-(organization, normalized email) failure budget lets anyone lock a known account for up to the window; this is an accepted tradeoff for limiting password guesses across IPs.
- Fixed sign-in windows can allow up to twice the failure budget across a window boundary; this is accepted for the simple process-local limiter.
- Subscribe handoff registers the live subscription first (per-connection queue), replays committed seq > after_seq ascending in bounded pages, flushes queued live seq > last replayed, then sends subscribed; clients dedupe by (channel_id, seq), allowing duplicates but no gaps. Full queues close with 4008, never silent loss, then reconnect/re-subscribe from each channel's last seq; session expiry/sign-out closes with 4001 and the client goes to Sign in.
- #22 implements channel create/list using session-derived Organization and Member only. Private creation inserts the creator into `channel_members` in the channel transaction; composite foreign keys bind memberships to both a Channel and Member in the same Organization. Listing uses one scoped query for public channels plus the caller's private memberships, with `Cache-Control: no-store`; membership management and message permissions remain later slices. Channel names retain the existing #23 string contract without additional limits or normalization.
- #17 implements the #23 message contract with session-derived Organization/sender and channels-owned visibility checks; inaccessible Channels return the same 404 for reads and sends. A messages-owned per-Channel counter is updated in the insertion transaction (no PostgreSQL sequence), so rollback consumes no number. The unique key (organization_id, sender, client_message_id) returns the canonical message for matching body/Channel and 409 otherwise; a concurrent duplicate rolls back its allocation before reading the committed winner. Message and cursor indexes and composite foreign keys ship in the same append-only migration; topic_id remains null.
- Message bodies are limited to 4000 Unicode scalar values because the spec states no size limit; NUL, empty and whitespace-only bodies return 400 before sequence allocation or writes.
- Maintainer-approved API contract (#17): message body is 1..=4000 Unicode scalar values (no NUL, not whitespace-only, whitespace preserved). Only the send route has a 32 KiB request cap (worst case ~24 KB JSON-escaped); every other route keeps 16 KiB.
  Stored bodies are not trimmed; leading and trailing whitespace remain part of the body and idempotency comparison.
- The per-Channel counter row serializes writes to a hot Channel; measure its throughput and contention in load test #20.
- #46 replaces the review-only module-direction fallback with a Tier 1 rustc-driver check of resolved HIR path segments (module aliases, local type-alias paths and re-exports), macro invocations/expansions (including empty/re-exported macros), type-dependent calls and resolved ADT field definitions. Type-alias paths are followed transitively with the referencing module as owner, preserving intermediate re-export modules; field checks use rustc's adjusted receiver and field index. Negative fixtures compile first with plain rustc, then fail under the checker in production and test configurations. `main`/`openapi`/`lib` remain composition exceptions: inferred values merely forwarded through root fields/functions (e.g. `let x = &state.hub`) and dependencies hidden inside nominal wrappers are not traced and remain review-enforced. The pinned toolchain's `rustc-dev` component is development-only, with `RUSTC_BOOTSTRAP` scoped to building the checker and no application dependency or crate split.
- #18 adds process-local, Organization/Channel-keyed live delivery with 256 queued events per connection and at most 256 subscriptions. Messages owns post-commit fan-out; Channels checks all candidate Members in one visibility query, avoiding per-recipient SQL. Shared canonical payloads keep fan-out bounded; overflow or authorization-query failure closes with 4008 for replay. Multiple server processes need shared publication/revocation before deployment.
- Replay registers live first, snapshots a committed high-water seq, reads 50-message pages, flushes queued newer events, then acknowledges subscribed. Cursors discard duplicates; an out-of-order live publication fills the missing committed prefix from history. Message persistence and sign-out run to completion independently of HTTP cancellation so commit cannot skip notification.
- Future WebSocket subscription cursors are clamped to the committed high-water seq so clients resume live delivery immediately after a database restore; database errors checking the session at connect close with 1011, reserving 4001 for ended sessions.
- Cookie WebSockets require one matching Origin: same Host with HTTPS by default (HTTP when cookie_secure=false), or an explicit comma-separated FUKULOW_WS_ALLOWED_ORIGINS allowlist. Forwarded headers never determine allowed Origins. Auth retains Bearer precedence; native Bearer requests need no Origin. Open sockets use the database expiry clock and immediate sign-out notifications; a lagging revocation receiver fails closed with 4001.
- WebSocket runtime serialization promotes the existing serde_json package to a production dependency. Test-only direct dependencies tokio-tungstenite and futures-util reuse the locked packages to exercise actual upgrade/frame/close behavior; no new locked packages or load tooling are added.
- Web boundary check (#48): detected syntax and limits live in the header of `web/scripts/web-boundary.ts`. Workers/SharedWorkers are forbidden outside the API layer (they can hide communication the scan cannot see); Vite `?worker` / `?sharedworker` imports and destructuring (inconsistent between .ts and .svelte) are known limits, tracked in #60. Revisit Workers when a real need appears, then scan the Worker script. A name bound to different tracked objects in different scopes is checked against all of them (alias analysis always terminates). Web storage is forbidden everywhere: there is no file-name exemption while `src/ui-settings.ts` does not exist. The helper's exemption must land in the same change as its guard (typed allow-list of keys and values, no free-form key or string value, tests that an invalid key or value cannot be stored); that work blocks the first web storage use.
- #53 runs expired-session cleanup after successful sign-in: one attempt per 60 seconds per process (shared across Organizations), deleting at most 1,000 expired rows of the signing-in Organization via an Organization/expiry index; row locks are skipped, SQL has a 1-second statement timeout and the whole attempt a 2-second deadline. Failures are logged and never fail authentication; failed/cancelled attempts also consume the interval. An Organization without sign-ins retains expired rows until a later sign-in wins the shared gate; busy Organizations can delay others. Restarts reset the gate; no scheduler or distributed coordination is added.
- #53 charges a sign-in's omitted-Organization 400 (zero or multiple Organizations) to its existing per-IP reservation before any account reservation or password work; no account is known, so no account budget is charged. Password-worker saturation tests inject dedicated semaphores into the shared handler implementation so they cannot occupy the production Argon2 workers used by parallel tests.
- #51 makes Channel names unique within an Organization across public/private visibility with a DB unique index on `(organization_id, lower(name COLLATE "C"))`: ASCII letters fold case, non-ASCII characters compare as-is, other Organizations may reuse names, and duplicate creates return 409 `ErrorBody`. Lists use `lower(c.name COLLATE "C"), c.id` for fixed ordering. Existing duplicates fail the new migration; the operator resolves them and re-runs, with no automatic rename or deletion. Skip an additional realistic rollback case: duplicate-name failures in the creator-membership transaction are covered by duplicate/concurrent tests, the existing `CHECK (false)` test covers membership-insert atomicity, and no further unrepresented failure mode is known.
- Invariants check (#47): a row counts a test only if CI runs it, referenced as `path::test_name` (backticks are references; `(todo)` stands alone). Refused: Rust `#[ignore]`, non-plain `#[cfg]`/`cfg_attr` on the fn, Vitest/Playwright skip/fixme/todo (incl. inside a skipped describe), and `web/e2e/**` (not run in CI until E2E joins it). Not detected statically: runtime skips (`test.skip(cond)`, `skipIf`, `ctx.skip()`), `cfg` on enclosing mods/files, early returns; `.only` is not scanned (vitest refuses it under CI). Details in the header of `web/scripts/check-invariants.ts`.
- #46 scope and approval: the maintainer moved #46 into Sprint 1 and approved the shipped scope (the resolved-path check above); the forwarded-value and nominal-wrapper limits stay review-enforced and are tracked in the follow-up Issue. The checker depends on unstable `rustc_private` APIs, so every Rust toolchain bump (`rust-toolchain.toml`, Dependabot or manual) must verify the checker still builds and its negative fixtures still fail; a bump that breaks it is not merged until the checker is updated.
- Web real-time (#19 PR 2): one WebSocket in `web/src/realtime.ts` subscribes watched channels from each timeline's last seq after history loads, resubscribes after every reconnect (4008: at once; other closes: backoff), and treats 4001 as Sign in. An echo settles a pending send only if sender is the signed-in Member and client_message_id matches. Sprint 1 acceptance: `npm --prefix web run e2e:compose` against `docker compose --profile caddy up` from an empty DB.
- Web boundary check (#60, extends #48): Vite `?worker` / `?sharedworker` imports (static, re-export, literal `import()`) are network uses allowed only in the API layer; destructuring from `window` / `globalThis` / `self` / `top` / `parent` (declaration, nested, assignment) is checked identically in `.ts` and `.svelte`; `top` and `parent` are global roots. Known limits: `frames[n]`, `opener`, `iframe.contentWindow`, dynamic keys. No scope analysis, by design: a parameter shadowing an alias name is a pinned false positive (fail closed). Not handled: object rest (`const { ...rest } = window`), array destructuring, destructuring in for-of and in function parameter defaults. Worker import detection is separate from checking the worker script itself: a worker file is only scanned by the normal per-file scan, so being importable from the API layer does not allow network operations inside the worker.
- #47: if a test title is defined more than once in a file and any definition is skipped/ignored, a `path::name` invariant reference to it is refused (a single key cannot say which definition is meant); this fails closed.
- #47 limit: the invariants check scans every `.rs` file under `server/`, so a `#[test]` in a file that is not part of the Rust module tree (e.g. an unreferenced `server/src/unused_guard.rs`) is accepted as an executed test. Reconciling with the real `cargo test -- --list` output is tracked in a follow-up Issue; until then reviewers check that referenced tests live in compiled modules.
- #51 disclosure: because Channel names are unique per Organization across visibility, a 409 on Channel creation lets any Organization member infer that a private Channel with that name exists (names only; no members or messages). Accepted by the maintainer; name-length handling is tracked in #63.
- #63 (maintainer-approved): Channel names have a maximum of 128 Unicode scalar values (`name.chars().count()` in Rust, `char_length(name)` in PostgreSQL, OpenAPI `maxLength: 128`); longer names return 400 `ErrorBody` before opening a write transaction. This explicit limit keeps even 4-byte names within the unique btree index's physical entry limit; an index storage error is not an API length policy. The server enforces the limit because generated TypeScript strings cannot. Empty names (whitespace is decided in #72), ASCII folding, per-Organization uniqueness, 409 and authorization are unchanged.
- #63 operator procedure: before deploying migration `202611090004_channel_name_length.sql`, stop Channel writes and run the read-only preflight below with the maintenance database role. This intentionally global maintenance query checks all Organizations because the CHECK must validate the entire table. If rows are returned, have the operator resolve their names explicitly (respecting the existing Organization-unique ASCII-folded index), then re-run the query until empty and deploy. If startup migration fails on `channels_name_length`, keep writes stopped, run the same preflight, resolve the reported names and restart to re-run the unchanged migration. The migration never truncates, renames or deletes data; an unresolved violation aborts deployment rather than silently changing Channel identity. The plain CHECK validates all existing rows during ALTER under an ACCESS EXCLUSIVE lock, which also blocks reads; this is accepted at the current scale. A general migration lock_timeout is out of scope.
  ```sql
  SELECT organization_id, id, name, char_length(name) AS scalar_count
  FROM channels WHERE char_length(name) > 128 ORDER BY organization_id, id;
  ```
- #72 Channel name whitespace: a name with leading or trailing whitespace (as `str::trim()` defines it, including Unicode whitespace) is rejected with 400 `ErrorBody` before any DB write; it is not trimmed. Whitespace inside a name is allowed. Why: silent trimming changes what the member typed and makes equality rules unclear, while accepting invisible differences allows look-alike names. Existing rows are never auto-fixed or deleted; empty-name rules are unchanged. Implementation (API, OpenAPI, tests, data check, optional DB constraint) is #77; max length stays in #63.
- #66 design (approved by the maintainer: option 2): module-direction blind spots. Reproduced against the current checker (both compile with rustc and pass it): (a) forwarded/inferred value: `channels` calls a root fn `crate::make() -> realtime::Hub`, binds it and passes it on without naming the type (`let h = crate::make(); drop(vec![h]);`); (b) root nominal wrapper: root defines `struct W(realtime::Hub)` with `impl W { fn count(&self) }`, `channels` calls `w.count()`. Not blind spots: a field read on the inferred value (`crate::make().n`) is already flagged; a generic/trait fn that the root feeds a higher value (`channels::keep(&state.hub)`, trait defined in `channels` and implemented in `realtime`) is legitimate dependency injection and must stay allowed.
  Options: (1) keep Tier 2 review (no cost; relies on reviewers, misses (a) and (b)); (2) add an inferred-type rule: in a body of module M, flag a binding or expression whose resolved type contains an ADT from a higher module (through generics, refs, tuples), without descending into root ADT fields, so mentioning `AppState` stays legal (closes (a); one more typeck-results pass, small CI cost, same `rustc_private` surface class); (3) also trace root fn/impl bodies called from M (would close (b) but flags legal uses, e.g. `channels/tests.rs` calling `crate::app(AppState{..})`, so it is refused). Recommendation: (2); (b) stays review-enforced and untraceable (visible only in root bodies).
  Classification for the implementation Issue: (a) inferred-type violations are Tier 1 and must FAIL (negative fixtures). (b) the root wrapper is a known-limitation fixture that is expected to PASS and is recorded as such; it stays Tier 2 (review). Positive fixtures that must PASS: `AppState` used by a lower module for lower/same-level fields; the DI generic/trait case above. Done means: no false positives on the real tree, small CI time impact (measured), and the added `rustc_private` maintenance cost evaluated from the result; the low-cost estimate here is a hypothesis. If false positives appear, the rule is dropped and Tier 2 stays.
- #73 changes #53: a sign-in reserves the process-wide 60-second start atomically, then spawns the run (sign-in never waits for SQL; a single-flight guard refuses a start while a run is in progress and is released on completion, failure, timeout or cancellation). A run cleans one Organization chosen round-robin over all Organizations by id (first id after an in-process cursor, wrapping to the smallest; constant memory), one 1,000-row batch with the #53 bounds. Guarantee: with T Organizations and cleanup repeatedly permitted, each Organization gets a batch opportunity within T permitted attempts, so a quiet Organization is no longer starved. The cursor advances after selection and before deletion, so skipped locks, delete errors, timeouts and cancellation still use that Organization's turn. Exception: if the selection query (or getting a connection) fails, the interval is consumed and the cursor stays, so that attempt serves nobody. Cancellation before the Organization is selected is the same exception (interval consumed, cursor unchanged). The selection reads only Organization ids across tenants (a tenant-scope exception like sign-in discovery); the delete stays Organization-scoped. Tests await the task through a `#[cfg(test)]` handle, so the cleanup tests moved in-crate; a task dropped at shutdown is fine.
