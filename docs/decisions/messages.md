# Decisions: messages

Channels, Messages, Topics, Replies and Unread. Writing rules and the other parts: [index](../decisions.md).

## Channels and Messages
- #725 A future external search engine writes an outbox row in the Message transaction and applies it after COMMIT through a worker.
- #725 Search generates a dedicated cursor key at process start to avoid reusing credentials or provisioning another secret. Cursors expire on restart.
- #301 author lookup caps input at 100 ids, dedupes and omits unreadable authors. A shared non-locking history snapshot covers access, authorship and retained identities to prevent directory expansion and authorization races.
- #149 usable managers add/remove and every Role can leave its own grant. Serialize private removal and its checks per Channel to preserve the last usable grant and any last manager (409).
- #231/#305 Role demotion or deactivation that loses a private Channel's last usable manager fails atomically with 409 `last_channel_manager` and no Channel details. Reuse #149's locks and check via the guard injected into auth to preserve module direction.
- #292/#311: a private Channel's creator gets a manager right for the grant's lifetime, independent of Role. A usable manager holds a usable grant and either the right or the Owner/Admin Role. A Member can manage the private Channel they create and add Members. Owner/Admin gains no implicit access. Guests cannot hold the right or add Members under least privilege (#294).
- #292/#311 The right lives only with its grant. Removal, leave or a change to Guest ends it. Renewal, re-grant or reactivation never restores it (#146, #149). Because creator identity was unrecorded, #292 skips backfill to avoid granting rights nobody chose. Private Channels without a usable manager remain allowed (#149).
- #292/#311 last_channel_manager counts both usable manager paths in authorize, SQL rechecks and Capabilities, protecting managed Channels on revoke, removal, leave and Role changes (#149/#231) or deactivation (#305/#237).
- #311 PATCH /api/v1/orgs/{org}/channels/{id}/members/{member_id} and `can_manage_managers` gate right changes. Reauthorize and validate the target even for no-ops, so stale UI state grants no authority.
- #311 Manager PATCH uses 400 `channel_manager_private_only`/`channel_manager_guest`, 404 `member_not_found`/`channel_grant_not_found`, 409 `last_channel_manager`. Uniform 404 `channel not found` hides inaccessible Channels, including reads/sends (#17).
- #311 Lock target Member NO KEY UPDATE before grants, clearing Guest-bound rights before Role UPDATE. Otherwise a send can hold Member SHARE waiting on the grant while the Role change waits on that same Member. Clear rights before Role reconciliation to preserve grant → Unread order across Channels. Right-only updates skip Unread triggers and preserve access, grant_id and subscription.
- #311 Lock the private Channel through COMMIT in the trigger so concurrent public visibility and manager-right changes cannot both commit, even in direct SQL. A plain cross-table check races.
- #149 durable UUID grant lifetimes fence old subscriptions through re-grant/renewal even after a lost fast signal. Subscriptions track the current access path. Public non-Guests ignore redundant grants and preserve continuous access through promotion/removal. A Role change requiring a grant captures its lifetime.
- #149 scope fast rechecks/failures to Organization+Channel for grant changes or Organization+Member for Role/activation. No-op grants skip recheck. Only the 30 s fallback scans all, limiting tenant work and failures.
- #149 API writes lock Organization → Channels by ascending id → Members → grants → #142/shared #135. Sends recheck Member/revision/private grant after BEGIN and hold Member SHARE/grant through COMMIT before exclusive #135, blocking intervening deactivation (#146). Mark-read releases its watermark barrier before Member/grant/position locks.
- #231 Private creation locks Organization NO KEY UPDATE then creator Member (same #146 shared lock through COMMIT) before new rows to stabilize the Channel set. Creator grant is atomic and scoped. Lists batch visibility/Unread in one no-store snapshot (#22/#142).
- #51 Unique Channel names span both visibilities in one Organization with `lower(name COLLATE "C")`. Existing duplicates abort migration for operator correction. Accept that creation's 409 exposes a private name to an Organization Member, without Members or Messages.
- #410 Archive is a Channel state, not access loss, so restore is lossless (grants, Unread, placements) and it reuses #307 `channel_list_changed`. Rejected: revoking access (loses Unread and grants, fights #311 guards), a new notice variant (a list refetch suffices), freeing archived names (restore could collide), 404 for archived placements (clients would treat it as access loss and reset A12). Sends and Moves serialize on the existing Channel row lock (`FOR SHARE` against archive's `FOR NO KEY UPDATE`, which leaves FK `KEY SHARE` unblocked).
- #299 Channel names are 1..=128 Unicode scalars and NUL-free (400 before a write transaction) for usable names within btree limits (#63). Rust, DB CHECK and OpenAPI enforce length.
- #299 migration validates rows before replacing the CHECK. Violations abort without rename/truncate/delete. Stop Channel writes, correct rows from `SELECT organization_id, id, name FROM channels WHERE char_length(name) NOT BETWEEN 1 AND 128` and re-run until empty. Accept ACCESS EXCLUSIVE (blocks reads too) during plain CHECK validation at current scale (#63).
- #72 Reject surrounding `str::trim()` whitespace (400) to avoid look-alikes and preserve the submitted name. Use API validation because PostgreSQL whitespace differs (#77).
- #17 Update a Messages-owned Channel counter inside the insert transaction. PostgreSQL sequences consume numbers on rollback. Accept hot-Channel serialization for gapless allocation.
- #17 Scope canonical intent to Organization/sender/client id. Changed body/Channel/Topic name_key/parent gives 409. Concurrent losers roll back allocation before reading the winner. Keep whitespace for byte-exact idempotency. Bodies require 1..=4000 Unicode scalars. Invalid length, NUL or whitespace-only input gets 400 before allocation.
- #146 History shares authorization and page data in one non-locking read-only REPEATABLE READ snapshot. Prior loss denies and authorized reads see no later Messages.

## Personal sections (#204, implemented)

- #204 sections belong to one Member in one Organization, including Guest; Owner/Admin have no override. Reason: personal grouping must neither grant Channel access nor affect another Member's view.
- #204 access loss hides but retains placement/order; regain restores it. Section/Channel deletion removes placements atomically; hidden Channel cleanup changes no exposed generation or notice. Reason: retain grouping without dangling placements or disclosing deletion after loss.
- #204 composite Organization/Member/section keys enforce placement ownership; unique Organization/Member/Channel enforces cardinality. Reason: application checks alone cannot prevent cross-owner or cross-Organization data.
- #204 moves, reorders and deletes serialize per Member; complete reorders use last-committing-writer-wins. Keep Organization -> sorted Channels -> Members -> grants lock order. Reason: atomic orders and delete races must not introduce a deadlock.

## Topics, Replies and Unread (planned, spec P1-P8)
- #148 First Message or Move creates a Topic to avoid empty Topics. Its main line follows the highest surviving creation position, so a Move preserves older Messages' age (#141). Paging uses fixed W-relative positions. #137 measures feasibility and stops for a maintainer decision on a miss. Paging cost remains a measured gate.
- #148 The W-relative baseline plus unique live Messages above W keeps replay/older pages from double-counting or dropping counts. Live-only Topics need a summary for a count.
- #142 Messages owns separate Channel/Topic read positions. The badge sums their counts (#148). Migration/grant triggers initialize existing scopes at committed seq, remove revoked rows and let later Topics inherit the grant baseline. First-fetch initialization would lose sends between grant and fetch.
- #142 Serialize access per Organization (seed 142) so concurrent Member/Channel creation cannot miss positions. New visibility takes shared #135 through COMMIT. Mark-read rechecks access after W before locking Member/position. Revocation deletes positions and denies waiting updates. Only new access initializes. Continuous Channel/Topic access survives redundant grants and non-Guest Role changes (#144).
- #142/#144 triggers mirror Channel visibility, including Roles and current public/private grants on reactivation; changes to visibility must update both predicates. The position/visibility equivalence test guards this duplication without reversing module ownership.
- #519 A3: list counts read per-scope append counters and correction rows, never `messages`. Statement-level triggers on `messages` and BEFORE triggers on positions and Mentions maintain them. Ordinals are always computed, never taken from the writer, so old-image statements stay exact. Cost: list O(Channels + unread Topics + corrections in (read, as_of]); send one counter UPDATE per scope for total and sender (upsert only for a new key); mark O(min(advance, tail)); Move and Delete O(changed rows). Rejected: range scans (grow with Unread), app-maintained counts (missed writers drift), per-Member counts (send fan-out O(Members)). Drift is clamped and logged; `message_counts_check` recounts.
- #142 Missing positions suppress only that Channel's Unread at committed seq (Topic W), log list inconsistency, persist nothing and keep mark-read 404. A zero position marks old history unread and a list-wide 500 hides unaffected Channels.
- #142 Accept serialized set-based work O(active Members + their Topics) on public Channel insert and O(visible Channels + Topics) on Member activation, with shared #135 until COMMIT. Remeasure larger Organizations.
- #142 Backfill blocks sends and Member/grant writes under SHARE ROW EXCLUSIVE. Work scales with visible Member×Channel pairs plus Topics. A 5 s startup lock wait cap does not bound the write outage after acquisition.
- [#620](https://github.com/tkakkie/fukulow/issues/620) Reuse the scoped Message creation index to save a heap row and index entry per send. The Channel counter is the sole allocator for Create and Move positions, with the Channel barrier protecting the write through COMMIT. Scoped keys bound replay and enforce uniqueness within each source, so the database permits a Create and Move at the same position. Replay fails closed on duplicates. Retain creation identity and tombstones for current-state replay without a past-body archive.
- #160 Event position and Message state version are separate. Version is the last affecting event position. Higher versions alone replace state, so replay/reorder/stale ACKs or pages converge. Delete is a terminal tombstone.
- #160 Past-body retention/erasure across edits, deletes, receipts and backups remains an open privacy/legal decision. Until then archive no past bodies and reveal no deleted content via replay, snapshots, search or counts. Tombstones prevent resurrection.
- #515 A creation-time SHA-256 digest of the original send intent, retained for the Message lifetime, keeps retry identity stable across edits without keeping plaintext in the receipt while retention remains open.
- #515 Expire operation receipts after 7 days to bound storage. Later retries are new requests and stale `expected_version` prevents re-execution.
- #141 One release renames Message.seq to created_seq and adds version/deleted and event seq/kind without aliases or a compatibility path. Nothing is deployed yet, the binary embeds web and Kotlin starts with the new shape.
- #515 uses Organization UUID epochs, explicit as_of_seq bootstrap and a Channel mutation floor to detect restore even beyond old cursors and expire unreconstructable pages. Owner-only rotation prevents ordinary traffic rotating epochs.
- #160 Required before any mutation ships are history_generation, snapshot_expired, an explicit bootstrap cursor and idempotent sends/mutations via receipts and expected_version. Mutable history invalidates fixed-W pages, cursors and blind retries.
- #160 Mutation thresholds are fixed before #141/#287 measurements to prevent result fitting. Do not relax budgets. Unevaluated work never passes. Formal evaluation follows #431.
- #160 The INVALID 2026-11-16 replay/migration results remain reference only. No `--settle-fixture` rerun gates this choice, which rests on deterministic buffer counts and settled WAL.
- #151 DM is a Channel kind for one immutable Organization-scoped Member pair. Omit name, visibility, Topics and manager rights to reuse seq, Replies, sync and Unread without applying private management. [Contract](../spec/dms.md)
- #151 POST /dms opens or renews the pair and GET lists authorized peer identity and Unread/Mention baselines. Exclude DMs from ordinary Channel lists/sections because they have no name or Topic navigation.
- #151 new sends hold peer eligibility through COMMIT (409 `dm_peer_deactivated` or `dm_peer_access_lapsed`). Authorized canonical retries resolve first so sending never renews access or undoes an accepted send.
- #151 DMs reject Topic intent and all grant/member APIs and management Capabilities. Exclude them from RoleChangeGuard and last-manager/grant counts so fixed participation confers no management and never blocks Role changes.
- #151 Reclaim only discovery revisions below the committed Member revision (never reset). SKIP LOCKED on one old counter, then delete ≤1,000 index rows and its counter once empty. Avoid Member/grant locks to preserve writer order and usable feeds.
- Mention unread is a separate displayed count on the existing Channel/Topic position (#148/#152), counting one accepted Mention per Message and excluding own Messages.
- #142/#143 client baseline selection (larger as_of_seq, then read_seq, then smaller counts, within one access generation) needs no server change. Reason: positions only advance within a generation, so counts at equal as_of_seq never rise with read progress.

- [#141](https://github.com/tkakkie/fukulow/issues/141) gives ordinary Members Move rights over chains they authored in full, with broader rights for usable management. This preserves ownership across Replies and prevents Organization Role from widening private access.
- [#141](https://github.com/tkakkie/fukulow/issues/141) uses one position per chain and preserves emptied Topic identity/read positions. Per-Message positions would multiply replay and write cost, and removing the Topic would reset Unread on revival.
- [#141](https://github.com/tkakkie/fukulow/issues/141) records a same-Topic receipt without a position. The key remains bound to the original request even if the chain moves later. Canonical retries return the original outcome alongside the current chain version and Topic.
- #141 rebuilds the main Unread index and adds `messages` indexes in the atomic migration. The nonconcurrent builds scan `messages` while migration locks can block reads and writes until COMMIT. The outage threshold remains open under [realtime decision 5](../spec/realtime.md#open-maintainer-decisions).

## Mentions (#152, specification for approval)

- #152 proposes exact `@{member:<lower-case UUID>}` tokens. Persist accepted ids and resolve current names so rejected tokens stay literal after grants. Shared shape is in OpenAPI. Syntax/disclosure approval stays under M1/M6.
- #152 Check current same-Organization active target access inside send (private Owner/Admin and public Guests need grants). Denied tokens expose no identity and create no count/Notification. DM B3 still governs peer-send refusals.
- #152 Commit Message and accepted Mention ids together and resolve authorized retries before target checks. Later access must neither rewrite an accepted send nor accept earlier rejected tokens.
- #152 Hold sorted sender/target Member locks before grants through COMMIT, maintaining #142/#135 and #151 discovery order to serialize loss without Member-after-grant deadlocks (M2).
- #152 Use Organization-scoped Message/Member FKs, unique Message/Member and member/Channel/Message indexes in Messages (M5) for atomic deduplication, batched unread ranges and tenant isolation.
- #152 Mention counts share Channel main/aggregate, Topic and DM Unread scopes and snapshots so mark/loss clears both without a second position or double-counting Reply/Topic projections (M3).

## Topics (#137, #138)
- #137 Messages owns Topic rows and atomic sends. Composite FKs bind nullable Message Topics to Organization and Channel. #139 adds an append-only migration.
- #137 Topic names use 1..=60 Unicode scalars and reject empty/NUL/blank/surrounding Rust whitespace (400) without trimming. ASCII-only folded identity is per Channel and preserves the first display name. Channel validation differs.
- #137 Atomically commit Topic create/join, Message, seq and summary under bounded send admission. Canonical intent includes normalized Topic name_key (null without Topic). Changes conflict with 409. Lost-response retries need no Topic UUID.
- #137/#515 Resolve and release #135 admission/barrier before one fresh snapshot of auth, W, M and data so mutable rows cannot exceed server-selected W. Fixed W below M expires. Admission refusal is 503 + Retry-After.
- #758 Reuse the current Topic summary when its last creation is at/below W. At or above the mutation floor only Creates follow W, so an indexed position probe and suffix count reconstruct older summaries. For the selected Topics, subtract later Creates from #519 A3 Unread and bound counted Mentions at W. [Earlier prefix-aggregation baseline](../measurements.md#topic-projection-paging-137)

## Replies (#139, #140)
- #139 Replies share send admission/barrier/transaction/publication and inherit committed parent's Topic and stable root. Scoped FKs and self-parent CHECK protect references, and committed immutable parents prevent cycles. Application writers/repairs must keep each Reply on its parent's root (or the parent itself), with null reply_root_id on roots and the committed parent id stored on each Reply. FKs alone cannot enforce this, so Move (#141) checks stored chain membership before rewriting a chain.
- #139 Compare reply_to before parent lookup. Inherited Topic is not intent. Canonical retries and changed-parent conflicts reveal no parent existence.
- #139 Chain reads union indexed root lookup and bounded reply_root_id/seq without recursion or a depth cap. Include the null-root Message. Resolve ambiguous COMMIT before a fresh authorization/data snapshot. Follow P6/#160 for fixed-W paging.
- #139 DeferredOrganizationAuth rejects Session/database errors before reading a send body and defers only Organization unavailability to validation, preserving 400-before-404, 401 and admission authorization.
- #139 Accept plain index and validated FK/CHECK migration locks/scans at current scale (#63). Timeout bounds lock wait only. Exclude non-Replies from the chain index to limit write/storage cost.
- #138/#515 Topic composition passes explicit initial timeline generation/W separately from visible records because positions need not be creations. Later pages prove no contiguity.
- #140 keeps one opt-in chain per Channel, merged by Message id and stable root. Use only last page seq for continuation so live appends neither skip siblings nor enter cursor/gap evidence.
- #140 composes over sync (or Topic sync) for confirmed-parent sends. Keep reply_to/id/body through pending/retry. Projection settlement obeys C5 and Session/read fences before teardown.

## Send limit (#306)
- #306 Per-(Organization, Member) bucket starts full at 10, refills 1/s. A person sustains less than 1/s. Bursts cover pastes/retries. Prevent one Member or stolen Session occupying all 256 Channel waiters.
- #306 Authorize before limiting, then admit, so denies stay 404 and 429 consumes no slot, seq or event. Reauthorized canonical retries skip the bucket so exhaustion never blocks recovery (S5).
- #306 Charge on limiter pass without refund so failing parents/rollbacks cannot loop for free. Treat DB failures without definite rollback as unknown. An extra free retry within 120 s costs at most one send. Double-charging honest C6 retries can throttle them.
- #306 Fail closed at capacity with uncharged 503 and Retry-After 1 s. Only full buckets are evicted so removal never resets debt. The single-process deployment keeps ≤100,000 in-process buckets (~70 B each, ~7.5 MiB with growth), ≤10,000 pending keys (~200 B each including watch, ~2 MiB), 16 waiters/key and 120 s unknown markers.
- #306 Identical waiters share the executed leader's result or failure, including paid admission 503. Re-execution would charge again/spend the free retry (#349). Only charged unknown COMMIT earns a marker, preventing chained free retries. Another intent starts fresh with neither outcome nor credit.
- #306 Operator env tunes burst/refill for single-Member CI load/E2E. Defaults/Compose keep 10 and 1/s. Preserve order, idempotency, caps and 503 fail-closed. CI overrides are not production-limit measurements.
